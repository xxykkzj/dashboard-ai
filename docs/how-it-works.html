How the app works

From a JSON file to a chart on screen, one step at a time.

This page follows one number from a file on disk to the screen. Keep js/main.mjs open beside it; it is about 250 lines and reads top to bottom.

First, what an ES module is

An ES module is a JavaScript file that says what it needs from other files with import and what it offers with export. The browser follows the imports and loads each file once. The .mjs ending just makes it obvious the file is a module.

The page loads only one script, js/main.mjs. Everything else arrives through imports. Paths are relative to the file doing the importing and must include the file ending.

Step 2: items, one object per card

Every card is a reporting item: a plain object in one of the files in js/items/.

FieldWhat it does
idUnique id, shown in the card footer. Also the element id, so #services/ITM-15 links straight to it.
tabThe tab the card belongs to by default. LAYOUT in js/items/index.mjs overrides it (see tabs and sections).
spanWidth on the 12-column grid: s3, s4, s5, s6, s7, s8 or s12. Add tall to span two rows. Also overridden by LAYOUT.
viewThe view to ask the data source for.
title, subCard heading and the line under it.
buildWhat the How it's built panel shows: tables, fields, logic and SQL.
render(host, data, state, ctx, more)Draws the item into host (the card body) from data (the view's answer).
also (optional)Extra views, e.g. { targets: 'vw_Targets' }. Their answers arrive in more.
params(state, ctx) (optional)Extra query parameters, e.g. the selected service.
deps (optional)State keys that should make this item draw again, e.g. ['txType'].
control(state, ctx, id) (optional)A control in the card header, made with segControl or selectControl.
global: false (optional)Ignore the period and phone-type filters.
kind (optional)'kpi' or 'hero' changes the card's look.

js/items/index.mjs gathers every item into one list, ITEMS, and also defines TABS and the presentation slides, STORY. This list is the item registry.

Tabs and sections: one layout for the whole dashboard

Which cards appear on which tab, in what order, how wide, and under which heading is set in one place: LAYOUT in js/items/index.mjs. Each tab is a list of sections; each section has a title and a list of [id, span] pairs.

  • When the registry loads, each item listed in LAYOUT takes its tab, span and section from it, so the dashboard, the item catalog and the Wanted list all agree.
  • main.mjs asks tabSections(tabId) for a tab's sections and draws one grid per section with a heading above it. The first section sits on the dark cover band, so its heading is read by screen readers but not shown; the tab title does that job.
  • Sections whose items are all switched off (for example Fuel exemption, see switching features off) disappear on their own.
  • An item not listed in LAYOUT still appears, on the tab named in its own definition, in a section called More, so nothing goes missing.

The item files in js/items/ group items by subject, not by where they are shown. Moving a card to another tab is a change to LAYOUT only.

Step 3: starting up

When the page loads, boot() in main.mjs runs:

  1. It creates the data source and loads the council reference files.
  2. buildShell() writes the tab links and, for each tab, a grid of empty cards using cardHTML(item). Each card body starts with a grey placeholder.
  3. bindControls() attaches the click and change handlers.
  4. showTab() reads the address, shows that tab and renders its items.

query() keeps each answer in a Map keyed by view name and parameters, so two items that read the same view share one request, and coming back to a tab is instant. If a view fails, the card shows a short error and the rest of the page carries on.

Step 4: state and filters

Step 5: tabs and links (hash routing)

The part of an address after # is the hash. Changing it does not reload the page, but the browser fires a hashchange event, and the back button works. The dashboard uses it to remember the tab:

  • #services shows the Services tab, and #value the Value tab.
  • #location/ITM-22 shows the Location tab, scrolls to the map and moves keyboard focus there.

Tabs are ordinary links (<a href="#services">), so they work with the keyboard and can be bookmarked. showTab() hides every tab panel except the current one and renders any item on it that is out of date.

Presentation mode

js/present.mjs shows the slides listed in STORY. A slide is a title and a list of item ids with spans. It builds the same card shell for each item and calls the same renderItem, so slides always match the tabs, and filters and drill-down keep working.
