Getting started

Run the dashboard on your computer and find your way around the folder.

mySA GOV Insights is a dashboard prototype built with plain HTML, CSS and JavaScript. There is no framework and nothing to compile: the files in the folder are the files the browser runs. These pages explain how it is put together and how to change it.

You need to know basic HTML. Everything else (how the CSS is organised, what an ES module is, how data becomes a chart) is explained as it comes up.

Run it on your computer

  1. Open a terminal in the project folder. In VS Code: Terminal then New Terminal.
  2. Start a local web server. Use whichever you have installed: In VS Code you can also install the Live Server extension, right-click index.html and choose Open with Live Server.
  3. Open the address it prints in Chrome, for example http://localhost:3000 or http://localhost:8080. These docs are at the same address with /docs/ on the end.
  4. Change something. Open data/mock/targets.json, change the target for transactionSuccess from 0.935 to 0.92, save, and refresh the browser. The status on the Overview tab changes.

Why double-clicking index.html doesn't work

If you open index.html straight from the folder, the address starts with file://. Browsers treat that as untrusted and block two things this dashboard needs:

  • JavaScript modules. The page loads js/main.mjs with <script type="module">, and that file imports others. Chrome only allows this over http://.
  • Fetching JSON. The mock data is read with fetch(), which is also blocked from file://.

A local server fixes both by serving the same files over http://localhost. Nothing leaves your computer. If you do open the file directly, the page shows a banner telling you to start a server.

Folder tour

index.html the page: masthead, cover, empty <main>, presentation shell css/ tokens.css every colour, font, size (light and dark). Restyle here. base.css reset, page grid, focus styles, reduced motion components.css how each component looks js/ main.mjs starts the app: loads data, builds tabs and cards, wires filters config.mjs mock or API, file paths, privacy threshold state.mjs the current filters and selections present.mjs presentation mode data/ source.mjs picks the data source mock-source.mjs answers each "view" from the JSON files api-source.mjs asks a real API for the same views ui/ building blocks: charts, maps, card shell, status, formatting items/ the reporting items, grouped by subject, plus index.mjs (tabs, layout, slides) vendor/ D3 and topojson-client, used only by the map data/ mock/ the mock data. Edit and refresh. reference/ council names, populations and boundaries docs/ these pages tools/generate-mock.mjs regenerates the daily mock data

Three ideas explain most of the layout:

  • Looks are separate from behaviour. CSS decides how things look. JavaScript decides what is on the page. You can restyle without touching JavaScript.
  • Data is separate from display. Charts never read JSON files. They ask the data layer for a named view and draw whatever comes back. That is what lets the mock data be swapped for a real API later.
  • Each reporting item is one object. A card on screen is described in one place: its title, the view it reads, how it was built, and a function that draws it.
