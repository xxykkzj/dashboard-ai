Item catalog

Every reporting item, its view, its data and its source tables.

Every card on the dashboard is a reporting item with an id such as ITM-05. This catalog is built from the dashboard's own registry (js/items/index.mjs), so it always matches the code. Select an id to open that item in the dashboard.

Ids are permanent labels, not a count: numbers are never reused, so there are gaps where items were retired (11 and 25).

  1. Loading the item registry… If this stays, check you are viewing through a local server.

Reading an entry

  • View(s): the first is the item's main view. Others, such as vw_Targets and vw_Events, are extra views listed in the item's also field.
  • Response shape: what the main view returns. Select it to expand. number[] means a list of numbers; ? means the field can be missing. The real API must return the same shape.
  • Mock data: the files the mock source reads to answer the view. Names in brackets are the field inside the file.
  • Source tables: the app database tables the real SQL view would read. Table names are real; column names are assumptions to confirm. Open How it's built on the card for the SQL.
