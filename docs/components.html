Component catalog

The building blocks, with live examples and the code that made them.

A component here is just a function. You give it an element (the host) and some data, and it writes HTML or SVG into that element. Nothing is hidden: open js/ui/charts.mjs and each function is 20 to 70 lines.

Every example below is live. This page imports the dashboard's real modules and calls them with a few made-up numbers, so hover and keyboard behaviour is the real thing. Colours come from tokens, so the theme button changes them too.

Three rules every component follows
  • It gets all its colours from CSS tokens, never a hex value in JavaScript.
  • It gives the chart a text summary (aria-label or a table caption).
  • It shows "No data for this period." instead of an empty box.

Formatting helpers

From js/ui/format.mjs. Use these so numbers and dates look the same everywhere.

FunctionExampleResult
fmt(n)fmt(42252.4)42,252
fmtC(n)fmtC(2284000)2.28M
pct(x, decimals)pct(0.932)93.2%
fmtMoney(n)fmtMoney(1790000)$1.79M
dfmt(iso, year)dfmt('2026-11-14')14 Nov
dRange(from, to)dRange('2026-10-30', '2026-10-31')30–31 Oct
escapeHtml(s)escapeHtml('A & B <x>')safe to put inside HTML

kpi(host, options)

js/ui/charts.mjs

A headline figure with its change on the previous period, a small trend line and, if a target is given, a status chip.

value, format
The number and a function that formats it (fmt, fmtC, pct).
delta, deltaText
Change as a fraction (−0.21) and the text to show ("21.1%").
goodUp
Set false when a fall is good news. Default true.
sparkData, sparkTarget
Daily values for the small chart, and an optional dashed target line.
range
Days in the period, used in "on the previous 30 days".
evaluation
The result of evaluate() from status.mjs. Leave out for no target.

lineChart(host, options)

js/ui/charts.mjs

One or more lines over dates, with a hover guide and tooltip. With two or more series each line is named at its end and in a legend.

dates
List of YYYY-MM-DD strings, one per point.
series
[{ name, values, color }]. Use var(--accent) then var(--accent2).
events
[{ from, to, label, kind }] shaded and labelled on the chart.
title
Used in the text summary for screen readers.
yFmt, tipFmt
Formatters for the axis and the tooltip.

lineChart with target and comparison

js/ui/charts.mjs

The same function with three more options. Use zero: false for rates that sit in a narrow band, so the line is not flattened against the top.

target
{ value, label } draws a dashed line and adds it to the legend.
compare
{ name, values } draws the previous period as a grey dashed line. Must be the same length as dates.
zero
false lets the axis start near the lowest value. Default true.

barChart(host, options)

js/ui/charts.mjs

Vertical bars for a handful of categories or periods. Always starts at zero.

labels, values
One label and one number per bar.
name
What the bars count, for the tooltip and legend.
target
{ value, label } dashed line.
events, dates, spanDays
To mark events, also pass each bar's start date and how many days it covers.

Live example

hbars(host, rows, extra, options)

js/ui/charts.mjs

Horizontal bars with a label on the left and a value on the right. The workhorse for rankings and shares.

rows
[{ label, value, text?, sub?, color? }]. text replaces the number on the right; sub is a second line under the label.
extra
HTML to add underneath, usually a legend(...).
options.max
Fix the scale, e.g. { max: 1 } for shares, or to compare two lists.

hbars with stacked parts and drill-down

js/ui/charts.mjs

Give a row parts instead of value to stack segments. Give it go to turn the whole row into a link or button: set changes state and hash moves to another item.

parts
[{ name, value, color }].
go
{ hash?, set?, label }. With hash the row is a link; without, a button.

funnel(host, steps, options)

js/ui/charts.mjs

Steps drawn as layers that narrow to the next step, with the share and number that stopped at each boundary. The largest drop is marked.

steps
[{ label, value }] in order. The first step is 100%.
options.noun
What is being counted, for the screen-reader summary. Default "people".

cohortGrid(host, cohorts)

js/ui/charts.mjs

A retention grid: one row per sign-up week, one column per week since. It is a real table, so screen readers can read every cell.

cohorts
[{ week, size, retained }] where retained[n] is the share active n weeks later and retained[0] is 1.

table(host, cols, rows, caption) with meter and spark

js/ui/charts.mjs

A plain table. Cells are HTML strings, so they can hold a meter(share) or a small spark(values) chart. Escape any text that comes from data with escapeHtml.

cols
[{ h, num? }]. num: 1 right-aligns the column.
rows
A list of rows, each a list of cell strings.
caption
Read by screen readers. Always give one.

heatGrid(host, options)

js/ui/charts.mjs

A day-by-hour grid shaded on the five-step sequential scale, with the busiest hour outlined and stated in words.

days
Seven labels, Monday first.
matrix
Seven rows of 24 numbers.
valueLabel
What is counted, e.g. "sessions".

statusChip(status, text) and evaluate(target, measure)

js/ui/status.mjs

Status is always a shape plus a word, never colour alone. evaluate compares a measure with a target from targets.json and returns { status, measured, text, now }.

status
'good' (On track), 'watch', 'action' or 'info'.
target.basis
'value' compares measure.value; 'perDay' compares current ÷ days; 'growth' compares the change from previous to current.

Scorecard (item ITM-00)

js/items/overview.mjs

The scorecard is not a helper but an item: its render function counts statuses and draws each measure as a bar between its action level and its target. To reuse the look, copy the .tally and .gauges markup from that function. The example calls the real item with made-up data.

data
{ days, measures: { key: { value } | { current, previous } } } from vw_Scorecard.
more.targets, more.events
From vw_Targets and vw_Events.

geoMap(host, options)

js/ui/geomap.mjs

The council map on real boundaries, drawn with D3, with inner Adelaide enlarged beside it. Needs the two scripts in js/vendor on the page. Try dragging, the view buttons, and arrow keys after tabbing into the map.

rows
One per council: the fields from lga.json plus users, per1000 and suppressed.
topo
The boundary file, already loaded as an object.
metric
'per1000' or 'users'.
threshold
Privacy threshold, for the wording of hidden councils.
selected, onSelect
The selected council code, and a function called with the new code (or null).

tileMap(host, options)

js/ui/tilemap.mjs

The same data as equal-sized tiles, one per council, so small councils are as visible as large ones. Takes the same options as geoMap, without topo, plus placeholder for where Adelaide sits on the main grid.

placeholder
{ col, row } from lga.json (metroPlaceholder).

cardHTML(item, state, ctx, options)

js/ui/card.mjs

The shell around every item: title, optional control, body, and the How it's built footer. You rarely call it yourself; main.mjs does it for every item in the registry. kind: 'kpi' on the item removes the frame, and kind: 'hero' gives the large first card.

Live example

segControl and selectControl

js/ui/card.mjs

Controls for a card header. They only produce HTML with a data-state attribute; one listener in main.mjs turns a click into setState. Use them in an item's control field and list the same key in deps.

segControl(key, label, options, current, scope)
Two to four choices as buttons. options is [[value, text], …].
selectControl(key, label, options, current)
A drop-down for longer lists.
