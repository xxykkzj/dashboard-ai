Accessibility and conventions

A checklist to keep, and how files, names and comments are written.

Government services must work for everyone, including people who use a keyboard, a screen reader, high zoom or reduced motion. This page lists what the dashboard already does, as a checklist to keep true when you change it, then the conventions the code follows.

Checklist for every change

Keyboard

  • Everything you can click, you can reach with Tab and use with Enter or Space. Use real <button>, <a href> and <select> elements; never a clickable <div>.
  • Focus is always visible. The outline comes from :focus-visible in css/base.css; don't remove it.
  • Each map is one Tab stop; arrow keys move between councils. A skip link jumps to the content.
  • Presentation mode is a dialog: the page behind can't be reached, Esc closes it, and focus returns to the Present button.

Screen readers

  • Every chart has a text summary. SVG charts use role="img" with an aria-label; tables have a <caption>.
  • Decorative things are hidden with aria-hidden="true" (legend swatches, the cover drawing, sparklines next to a number).
  • Changes are announced. Filter and slide changes write to a live region (#announcer, aria-live="polite") through announce() in main.mjs.
  • State is exposed: toggle buttons use aria-pressed, expanding panels use aria-expanded and aria-controls, the current tab has aria-current="page".
  • Text only for screen readers uses the sr-only class.

Colour and contrast

  • Colour is never the only signal. Status has a shape and a word; availability bars differ in height; hidden councils are hatched; the largest funnel drop has a tag.
  • Text on a coloured mark uses the matching "on" token (--on-accent, --on-seq-hi), and labels beside a mark use the normal text colour, not the series colour.
  • Check both themes. Aim for 4.5:1 contrast for text and 3:1 for chart marks against their background.

Motion, zoom and small screens

  • Animations stop for people who ask for reduced motion. The rule is in css/base.css; in JavaScript, check reduceMotion() from js/ui/motion.mjs.
  • The page works at 390px wide with no sideways scrolling. Only tables scroll sideways, inside their own .tscroll box.
  • Sizes that hold text grow with the text. Test at 200% browser zoom.

Words

  • Plain Australian English, sentence case, no jargon: "phone type", not "platform"; "council", not "LGA".
  • Buttons say what they do: "Show as table", "Whole state".
  • The dashboard shows figures, not commentary. Don't add text that interprets or recommends.

Privacy

  • Location is council-level only. Councils under the threshold in js/config.mjs (suppressionThreshold, 10) are left out by the view, not just hidden on screen.
  • No names, contact details or raw coordinates reach the browser.

How to test

  1. Keyboard only. Put the mouse away and do a full task: change the period, open a tab, select a council, run the presentation.
  2. Lighthouse. In Chrome DevTools, Lighthouse then Accessibility. It catches missing labels and low contrast.
  3. A screen reader. NVDA on Windows (free) or VoiceOver on Mac (Cmd + F5). Listen to one chart and one table.
  4. The check script, if you have Python and Playwright: it opens every tab at desktop and phone widths and reports errors and sideways scrolling.

Conventions: files

KindWhereNaming
Reporting itemsjs/items/<tab>.mjsGrouped by subject, lower case. Where each item appears is set by LAYOUT in js/items/index.mjs. Ids are ITM-00 upward and never reused.
Building blocksjs/ui/One file per family: charts.mjs, geomap.mjs. Functions are verbs or nouns in camelCase: lineChart, statusChip.
Datajs/data/Views are vw_PascalCase, matching the SQL view.
Mock datadata/mock/kebab-case.json, fields in camelCase, an _about field first.
Stylescss/Tokens, then base, then components. Class names are short and lower case (.card, .hrow); a prefix groups a component (.gm- map, .fnl- funnel, .deck- slides).

Conventions: code

  • Comments say why, not what. Each file opens with a short block explaining its job. Inside, comment the surprising line, not the obvious one.
  • No colours in JavaScript. Pass token names: color: 'var(--accent)'.
  • Escape text from data. Anything from a data source that goes into HTML passes through escapeHtml().
  • Items don't fetch. They name a view and draw what arrives. Only the data layer knows where numbers come from.
  • State changes go through setState. Never assign to state from a component.
  • Dates are YYYY-MM-DD strings in data, and are formatted only at the last moment with dfmt or dRange.
  • Every new view is written down in the README data contract and in docs/items.mjs.
