Mock data guide

Every JSON file and field, with worked examples.

All figures on the dashboard come from JSON files in data/mock/. Edit a file, save, refresh the browser, and the dashboard changes. Nothing is cached. Every file starts with an _about field that explains it.

JSON is strict

Use double quotes, no comma after the last item, and no comments. If a file is not valid, the dashboard shows a banner naming the file. VS Code underlines the mistake in red.

The files at a glance

FileWhat it drives

events.jsonCampaigns and incidents shaded on charts.
value.jsonAssumptions behind the value estimate.
retention.jsonWeekly sign-up cohorts for the retention grid.
services-detail.jsonRegistrations due to expire, time to complete, payment amounts.
operations.jsonNew version uptake, notification settings, backend response times.
lga-activity.jsonHow likely residents of each council are to use the app. Drives the map.
usage-by-hour.jsonThe shape of a typical week for the day-by-hour grid.
../reference/lga.jsonCouncil names, populations, ABS codes and tile positions.
../reference/sa-lga-2023.topo.jsonCouncil boundaries for the map. Not hand-edited; see the recipe.

daily-metrics.json

360 days, two rows per day (ios and android). The period filter takes the last 7, 30, 90 or 180 days, and the same number of days before that for comparison.

FieldMeaning
date, platformThe day and ios or android.
activeUsersPeople who used the app that day.
newAccountsAccounts created.
credentialsAddedCredentials added to wallets.
credentialChecks, credentialChecksFailedVerifications, and how many did not pass.
transactionsFinished, transactionsCompletedFinished = completed + failed. Success rate = completed ÷ finished.
notificationsSentPush notifications sent.

This file is generated. For a new scenario, change PARAMS at the top of tools/generate-mock.mjs and run node tools/generate-mock.mjs. For a one-off tweak, edit rows by hand.

reference.json

FieldMeaning
uniqueUsersFactorTurns average daily users into unique users for a period. Only needed because the mock stores days.
onboardingFunnelSteps with a rate: the share that continues from the step before. Optional rateIos / rateAndroid.
transactionTypesEach service: key, label, share of all transactions, successAdjust, and its funnel steps.
reminderFunnel, fuelExemptionRates and categories for those two journeys.
credentialTypes, checkMethods, failureReasonsLists with shares. Shares in a list should add to 1.
providersBackends, each with incidents: a date mapped to "degraded" or "down".
downtimeMinutesMinutes lost per incident day, used for uptime.
appVersions, notificationTypesShares and rates for those tables.

targets.json

FieldMeaning
keyWhich measure. Must match a key in vw_Scorecard.
labelName shown on the scorecard.
basisvalue: compare the rate itself (0 to 1). perDay: compare the period total ÷ days. growth: compare change on the previous period (0.01 = 1%).
targetAt or above this is On track.
actionBelow this is Action. In between is Watch.

events.json

FieldMeaning
idAny unique text.
kindcampaign (blue band) or incident (red band).
from, toFirst and last day, inclusive, as YYYY-MM-DD.
labelShort name written on the chart.
noteOne sentence shown under the chart and on the scorecard.
affectsThe measures the event changed: any of active-users, new-accounts, transactions, credential-checks. The event is drawn only on charts of those measures. Leave it out to draw it on every chart. The scorecard lists every event in the period.

value.json

FieldMeaning
costPerTransactionCost to government of one transaction at a counter, by phone, on the website and in the app.
minutesSavedPerCounterVisitUsed for the hours-saved figure.
services[].otherwiseWhere an app transaction would have happened without the app. Shares add to 1.
services[].otherChannelsPer30DaysHow many of that service still happen outside the app in 30 days.

Change a target

In targets.json, set the new-accounts target to 1,500 a day:

Refresh. On Overview, the scorecard, the New accounts figure and the dashed line on New accounts per week (now 10,500, seven days' worth) all move, and the status changes from On track to Watch.

Add an event

Add an entry to the events list in events.json. It appears on the charts of the measures in affects, when the period includes its dates; switch the period to 90 days to see older ones.

Make a funnel step worse

In reference.json under onboardingFunnel, lower a step's rate, for example "First credential added" from 0.79 to 0.6. The onboarding funnel narrows there, and the onboarding measure on the scorecard falls with it.

Raise use in one council

In lga-activity.json, raise adoptionWeight for a council, say Ceduna (CED) from 0.36 to 0.7. Its colour on the map deepens and its rank in the council profile rises. Other councils fall slightly, because the same users are being shared out.
